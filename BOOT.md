# AERA standalone VM — engineering preview

AERA boots its own Linux kernel and Debian minimal userspace, starts a local graphical session using Xorg and Openbox as temporary display/window infrastructure, and launches AERA Shell fullscreen as an unprivileged user. This is a standalone guest, not a hosted application masquerading as an OS. Rust kernel and native compositor are separate roadmap items.

The first target is x86-64 QEMU. The builder runs on a disposable Debian/Ubuntu x86-64 Linux environment with root privileges, creates a new directory and a regular qcow2 artifact via guestfish (never a host disk). Debian stable (bookworm) packages are fetched at build time; reproducible snapshots, signing and offline distribution are pending. Kernel and initramfs are exported alongside the image for direct QEMU boot; this is not yet a UEFI installation image. ARM64 and Apple Silicon guest images require architecture-specific package/kernel builds and boot validation. An x86-64 image can be emulated on Apple Silicon, not hardware-accelerated as ARM64.

Build via the experimental CI workflow or locally in a disposable Ubuntu x86-64 VM: install debootstrap, qemu-utils, libguestfs-tools, then cargo build -p aera-shell --release and run sudo bash os/build-image.sh dist/aera target/release/aera-shell. Do not run on a production host. Start via bash os/run-vm.sh dist/aera. GUI uses virtual VGA and software Vulkan as fallback; no performance claim. Network is disabled at runtime by default. No login service, no remote access and no host shared folders. Guest is disposable, not secure for production.

Acceptance: boot reaches multi-user systemd, aera-session service runs as aera user, X server and shell launch, interactive desktop is visible, reboot/shutdown works. CI smoke uses serial journal marker emitted only after shell process and X window are observed; human screenshot and input test still required. Never publish a successful boot claim before observed evidence.
